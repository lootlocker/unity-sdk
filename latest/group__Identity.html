Identity

Detailed Description

Work with the cross-game identity behind a player's sessions.

An identity is the human behind one or more player accounts in a publisher, shared across every game that publisher owns. Use the identity methods to read the identity a session is linked to, look identities up, record a provider credential against an identity, and preview or execute a merge of two identities that turn out to belong to the same person.

Merging is destructive and never happens automatically: LootLocker returns the games in which both identities have a live player and the calling code must choose which player to keep in each.

Get the identity the current session is linked to, including the publisher it belongs to, the provider credentials linked to it, and per game the first and last session times and the session count.

The identity is taken from the session token, so a caller can only ever read their own identity. Use LootLockerIdentityResponse.providers to discover the credential ids that UnlinkProvider takes.

The session must be linked to an identity; a session that is not is answered with 403.

◆ LinkProvider()

void LootLocker.Requests.LootLockerSDKManager.LinkProvider ( LootLockerIdentityLinkRequest request,
Action< LootLockerIdentityLinkResponse > onComplete,
string forPlayerWithUlid = null )
inlinestatic

Record a provider credential against the identity of the current session, so a later session presenting the same credential resolves to this identity instead of minting a second one.

Linking is idempotent: a credential this identity already owns answers created = false. When another identity in the publisher owns the credential the call answers 409 and links nothing; the merge offer is surfaced on LootLockerIdentityLinkResponse.conflict and can be resolved with MergeIdentities. LootLocker never links a credential across identities on the player's behalf.

The backend stores the provider slug exactly as it is sent, so always send the canonical enum member; sending an alias would make the stored slug differ from what GetIdentity reports for other credentials of the same provider.

◆ MergeIdentities()

void LootLocker.Requests.LootLockerSDKManager.MergeIdentities ( LootLockerIdentityMergeRequest request,
Action< LootLockerIdentityMergeResponse > onComplete,
string forPlayerWithUlid = null )
inlinestatic

Merge another identity into the current one, keeping the current identity.

The merged identity is tombstoned, its credentials and player links move to the kept identity, and its sessions are revoked. Every game in which both identities have a live player must carry a resolution naming the player to keep; the other player of that game is soft-deleted. A missing or invalid resolution answers 400 and writes nothing.

This is destructive and never runs automatically. Get the conflicts from PreviewIdentityMerge (or from the conflict of LinkProvider) and let the player choose.

void LootLocker.Requests.LootLockerSDKManager.UnlinkProvider ( string credentialId,
Action< LootLockerResponse > onComplete,
string forPlayerWithUlid = null )
inlinestatic

Remove a provider credential from the current identity.

Get the credential id from LootLockerIdentityResponse.providers (or LootLockerIdentity.GetProviderCredentialId) after a call to GetIdentity. The provider's own user identifier is never returned by GetIdentity, so the id is the only reference available to a game client.

The last remaining credential cannot be removed, because the identity would become unreachable; that case is answered with 422.

credentialIdThe ULID of the credential to remove, as reported in LootLockerIdentityResponse.providers.
